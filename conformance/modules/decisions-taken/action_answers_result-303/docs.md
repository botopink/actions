# Decision 303 — An action answers `@Result`; there is no `ActionOutcome`.

The example is a newsletter action written as an `async` function, `subscribe`, which answers `Async<Result<Subscribed, ActionError>>` like any asynchronous function that can fail; the `async` marker is what lets a body that answers `Async<…>` return its value and lets `welcome` and `main` `await`. `return Subscribed(email: email)` is its `Ok`. Each `throw` is an `Error` value, not a raise: `ActionError.Unauthorized(message: …)` when there is no session, and `ActionError.Input(fields: …)` when the e-mail has no `@`, with the field messages keyed by name in a `Dict<string, string[]>`. `ActionError` is the library's sum type, with one case per outcome, and each case is an HTTP status on the wire. `Input`, `BadRequest`, `Unauthorized`, `Forbidden`, `NotFound`, `Conflict`, `TooManyRequests` and `Internal` are the whole list. There is no `ActionOutcome` record, no `ActionErrorCode` and no `orError()`.

The caller gets the same `Result` back. `show` reads it with one exhaustive `case`: `Ok(s)`, `Error(Input(fields))`, `Error(Unauthorized(message))` and `Error(_)` for the remaining cases. `welcome` reads it with `try await`, so an `Error` from `subscribe` becomes `welcome`'s own answer without being unwrapped. The program prints `subscribed ana@example.com`, `check email`, `log in: User must be logged in.` and `welcome ana@example.com`. The envelope's `{data}` / `{error}` JSON, which carries the outcome in the envelope's `payload`, is protocol only and never shows up in this code. The `#[action]` wrapper that registers such a function and answers `Error(Input(…))` before calling it is rakun's.
